YEET便をブラウザだけで出した理由

アプリを入れてもらう前に、まず一回触ってもらいたい。そのための最短経路が「Xの投稿をタップ → そのまま遊べる」だった。

ストアより先に、リンク

インストールの壁は想像以上に高い。とくにバカゲーは「30秒でわかるかどうか」がすべてに近い。だから HTML + 物理エンジン（Matter.js） の一式を GitHub Pages に置き、スマホの縦画面前提で操作をフリックだけにした。

ルールは故意に雑

荷物をつまんで飛ばし、トラックの荷台（センサー）に入れたら加点。反発や回転を少し盛って、意図どおりに飛ばない感じを残している。上手くなった実感より、「物理が暴れての面白い」を優先した。

なぜサイトの中に置くか

単体のゲームURLだけだと、遊んだあと行き先がない。ludofolio 側にトップ・運営情報・プライバシー・制作メモをまとめておくと、

  • 次の作品への導線が作れる
  • 広告や解析を入れるときの体裁が揃う
  • 「誰が何をしているサイトか」が説明できる

という実務的な利点がある。収益化はアクセスが先。中身のあるページを増やしつつ、遊べる入口は常に目立たせる方針。
